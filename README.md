# 内容工作台

给用 AI agent 做小红书、抖音内容的创作者：把稿件、生产流水线、平台后台数据、采集的爆款笔记和对标账号放在一个页面里，
看清哪些内容发了、表现如何、哪类选题真正涨粉，并让 agent 帮你拆解爆款、推荐选题。

它是一个 skill：装进 Claude Code（或其他支持 `SKILL.md` 的 agent）后，对 agent 说「建工作台」就能开始。

## 能做什么

| 视图 | 内容 |
|---|---|
| 总览 | 待办、账号表现、主力方向、最近发布 |
| 在制品 | 每期内容卡在哪个阶段（可选，需要按期组织的流水线） |
| 口播稿 | 稿件文件夹里的成稿，以及有没有发出去 |
| 数据表现 | 各平台的播放、收藏率、涨粉效率、开场留存 |
| 选题报告 | 按选题方向统计转化效率，给出主力方向和降权方向；结合对标账号生成选题推荐 |
| 对标账号 | 同赛道账号的近期爆款、标题模式、相对倍数 |
| 采集箱 | 用插件采集的笔记，选中后由 AI 做爆款拆解或多篇共性分析 |
| 拆解报告 · 爆款库 | 拆解结果，以及从中提炼的可复用开场、结构、话术 |

## 工作原理

工作台要回答的是：**哪些写法对你的账号真的有效**。这需要三样东西连起来：

| 你提供 | 放在哪 | 用来回答 |
|---|---|---|
| 稿件（口播稿或正文） | 一个 Markdown 文件夹，或按期组织的生产流水线 | 这条作品用了哪些开场、结构、话术 |
| 平台数据 | 创作者后台导出的作品数据表格，每个平台一个文件夹 | 这条作品表现如何 |
| 标题 | 稿件的文件名 / 文件夹名，和平台上的发布标题 | 把稿件和它的数据对上 |

闭环是这样转的：

```
采集外部爆款 → 拆解 → 保存到爆款库 → 写稿时取用 → 发布 → 导出平台数据
      ↑                                                        ↓
  选题推荐、写稿优先用「优先」的资产  ←  资产评级  ←  复盘爆款库：读稿件判断用了哪些资产，把数据记上去
```

- 工作台按标题把稿件和平台上的发布自动关联；对不上的在 `local/status.md` 的「发布关联」里写一行
- 写稿时在正稿后面记一节「资产使用记录」，复盘时就能准确知道每条作品用了什么
- 平台数据更新后，爆款库页提示有几条作品待回流；点「生成复盘建议」，逐条确认后写入
- 每条资产的评级来自使用记录：相对账号基线（各项指标的中位数）明显更好两次以上为「优先」，明显更差两次以上为「降级」
- 少了稿件，不知道用了什么；少了平台数据，不知道效果；标题对不上，两边连不起来。
  三样里任何一样缺了，选题报告和爆款库都只能停在「待验证」

## 先看效果

```
python3 scripts/serve.py --demo
```

用虚构数据打开一个完整的工作台（端口 8770），不需要任何配置。

## 安装

1. 把仓库放进 agent 的 skill 目录，文件夹名就是 skill 名：

   ```
   # Claude Code，个人级（所有项目可用）
   git clone <仓库地址> ~/.claude/skills/content-workbench
   # 或项目级：放到项目的 .claude/skills/content-workbench
   ```

   其他支持 `SKILL.md` 的 agent，放进它的 skill 目录即可。

2. Python 3.11+（macOS 自带的 `python3` 是 3.9，需另装：`brew install python`），然后 `pip3 install -r requirements.txt`
3. 视频笔记转写（可选）：`ffmpeg`，以及 `requirements.txt` 里注释掉的两项
4. 本地分析：默认调用本机的 Claude Code（`claude` 命令）；用其他 agent 时换成它的非交互命令，见 `local/config.toml` 的 `[analysis]`
5. Chrome 采集插件：`chrome://extensions/` → 开发者模式 → 加载已解压的扩展程序 → 选 `clipper/`

装好后对 agent 说「建工作台」。

## 接入

对 agent 说「建工作台」，它会按 `SKILL.md` 带你走一遍：先讲清上面的原理，再逐项配好稿件、平台数据、
生产流水线（可选）、账号定位和选题分类，最后检查稿件和发布记录关联上了多少。

手动接入：

```
python3 scripts/onboard.py init      # 从 local.example/ 建出 local/
# 编辑 local/config.toml
python3 scripts/onboard.py check     # 检查路径、平台导出、稿件、分类，以及稿件和发布的关联
python3 scripts/onboard.py scan 目录  # 有生产流水线时，扫一遍文件夹起草阶段配置
python3 scripts/serve.py             # 打开本地工作台
```

## 两份工作台

- **本地工作台**（`scripts/serve.py`，或双击 `打开工作台.command`）：每次打开都读最新数据。
  插件采集、视频转写、新增稿件、放入新的平台导出，5 秒内自动显示；放入新导出后选题报告自动重算。
  页面上的分析调用本机 agent，状态改动和分析结果存在 `local/data/state/`。
- **线上工作台**（可选）：发布到 claude.ai 的页面，可以换设备看。对 agent 说「同步工作台」，
  它会合并两边的状态和分析，再发布最新数据。

## 采集插件

- **笔记页**：点「抓取这一篇」，正文、互动数、评论、视频直链进采集箱
- **账号主页**：点「抓取这个主页」，账号的笔记列表进对标账号
- 只读取你正在看的页面里已经加载好的数据，点的那一刻不会向平台发任何请求

**依次更新对标账号**是实验功能：插件会在你的浏览器里依次打开采集过的账号主页，读取最新一页笔记。
可以手动开始，也可以设成每周提醒或每周自动运行。
这是自动化访问，平台可能据此判定账号行为异常，最坏情况是账号受限，也可能违反平台用户协议。
默认关闭，首次使用要勾选同意，自动运行还要再确认一次。限制写在代码里（`clipper/shared.js`）：

- 每次最多 10 个账号，5 天内采过的跳过，顺序每次随机；两次至少间隔 7 天，仅在 9:00–23:00 运行
- 不滚动，只读打开主页时加载的笔记；每个主页停留 6–30 秒，账号之间 20 秒至 4 分钟，长尾随机
- 出现验证页或安全提示立即停止，14 天内不再运行，自动运行降为提醒
- 自动运行只在电脑 5 分钟内有操作时进行，到点时间在所选时段内随机

再次采集同一个账号时，新读到的笔记并入原有记录，不会覆盖更早的笔记。

## 常见问题

| 现象 | 处理 |
|---|---|
| 双击「打开工作台」后提示 Python 版本 | 安装 Python 3.11 以上（`brew install python`），再双击 |
| 插件采集成功，工作台里没出现 | Chrome 改过默认下载位置时，把 `local/config.toml` 的 `download_inbox` 改成「Chrome 下载目录/xhs-inbox」；Chrome 开了「下载前询问保存位置」会每次弹窗，可以关掉 |
| 点「分析」提示没有找到 Claude Code | 安装 Claude Code，或在 `[analysis]` 换成你在用的 agent 命令 |
| 平台数据读不到 | `python3 scripts/onboard.py check` 会指出是哪个平台、缺哪一列；导出表的表头和配置里的列名要一致 |
| 插件提示「改用 DOM 兜底」或读不到笔记列表 | 小红书改版了页面结构，需要更新 `clipper/extract.js` |

目前只在 macOS + Chrome 上完整测过。Windows 和 Linux 上本地工作台能跑（打开文件夹分别用资源管理器和 `xdg-open`），
双击启动只有 macOS 的 `打开工作台.command`，其他系统用 `python3 scripts/serve.py`。

## 使用边界

- 插件只读取你自己正在浏览的页面，数据只落在本机，仅供个人内容分析；请遵守平台的用户协议
- 「依次更新对标账号」是自动化访问，有账号被判异常的风险，默认关闭；开启前请读插件里的风险说明

## 隐私

- 平台数据、稿件、采集内容都只在你的电脑上处理；`local/` 不进仓库
- 本地工作台只监听 `127.0.0.1`，接口需要启动时生成的口令
- 分析时，提示词会发给你配置的 agent（默认 Claude Code）；同步时，数据会发布到你自己的线上工作台
