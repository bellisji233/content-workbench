# 小红书采集插件

在小红书页面点一下，把当前页的数据落进本地收件箱。不上架商店，本地加载，零成本。

- **笔记页**：采集笔记内容，进工作台的采集箱，供爆款拆解
- **账号主页**：采集主页信息和笔记列表，进对标数据，供选题推荐和标题模式分析

## 安装（一次）

1. Chrome 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选中 `clipper/` 文件夹
4. 建议点一下扩展的图钉，把它固定在工具栏

改过代码或换过目录后，在 `chrome://extensions/` 里点插件卡片上的刷新按钮；
目录换了位置要先移除旧的，再按上面第 3 步重新加载。

## 用法

### 笔记

1. 打开一篇笔记（`xiaohongshu.com/explore/...`）
2. **想要评论区就先往下滚一下** —— 评论是懒加载的，没滚到就抓不着
3. 点插件图标 → **抓取这一篇**

### 对标账号主页

1. 打开对标账号的主页（`xiaohongshu.com/user/profile/...`）
2. 想多采几条就往下滚几屏 —— 笔记列表是滚动加载的，滚过的都会采到
3. 点插件图标 → **抓取这个主页**

每周一次，把几个对标账号依次过一遍即可。采集过的账号插件会记住。

### 依次更新对标账号（实验功能）

弹窗底部点「依次更新对标账号」，会打开一个页面：插件在你的浏览器里依次打开采集过的账号主页，
读取最新一页笔记，结果和手动采集一样进对标数据。

这是自动化访问，和手动采集不同：平台可能据此判定账号行为异常，最坏情况是账号受限，也可能违反平台用户协议。
默认关闭，首次使用要勾选同意。规则写在 `shared.js` 里：

- 每次最多 10 个账号，最久没更新的优先，5 天内采过的跳过，顺序每次随机
- 两次至少间隔 7 天（中途停止也算一次），仅在 9:00–23:00 运行
- 不滚动，只读打开主页时加载的笔记；每个主页停留 6–30 秒，账号之间 20 秒至 4 分钟，长尾随机
- 遇到失败立即停止，不重试；只读取，不做点赞、关注、评论
- 跳到验证或登录页、页面出现安全提示时，立即停止，14 天内不再运行

再次采集同一个账号时，新读到的笔记并入原有记录，更早的笔记不会丢。

#### 定期更新

同一个页面底部可以设「每周哪天、哪个时段」，到点的具体时间在时段内随机：

- **到时提醒**：弹系统通知，插件图标出现「!」，点通知打开更新页，自己点开始
- **到时自动运行**：要再勾一次确认。只在电脑 5 分钟内有操作时运行，开始前倒数 15 秒可取消；
  Chrome 关着或电脑休眠时顺延。出现验证页时自动运行会降回提醒

定时由插件后台（`background.js`）负责，访问循环在更新页面里跑（`batch.js`）。

### 收进工作台

两种采集都写到 `~/Downloads/xhs-inbox/`。本地工作台开着时几秒内自动收进来，也可以手动收：

```
python3 scripts/ingest_inbox.py
```

- 笔记 → `local/data/inbox/`，按 noteId 去重，视频笔记会自动起转写
- 账号主页 → `local/data/benchmark/{userId}.json`，并重算对标汇总

## 抓得到什么

| 字段 | 图文笔记 | 视频笔记 | 账号主页 |
|---|---|---|---|
| 标题、正文、话题标签 | ✅ | ✅（简介，不是口播） | — |
| 点赞 / 收藏 / 评论数 | ✅ | ✅ | 每条笔记的点赞 |
| 作者、发布时间 | ✅ | ✅ | 昵称、简介、粉丝数、每条笔记的发布时间 |
| 图片原图链接 | ✅ | 封面 | 封面 |
| 评论区（前 20 条） | ✅ 需先滚动 | ✅ 需先滚动 | — |
| **口播文案** | — | ❌ 页面里没有，走本地转写 | — |

视频笔记的口播文案不在页面里，要走本地转写：
`下载 → ffmpeg 提音频 → faster-whisper`，见 `scripts/transcribe_inbox.py`。

## 数据从哪来

读页面的 `window.__INITIAL_STATE__` —— 小红书把结构化数据放在那里，
比 DOM 选择器稳得多（类名是构建时哈希的，改版就失效）。

- 笔记页拿不到时退回 DOM 兜底，弹窗会提示「字段可能不全」，采集结果的 `source` 写明走的哪条路
- 账号主页的读法，「依次更新对标账号」和手动「抓取这个主页」用的是同一套（`extractProfile`）

## 出问题时

| 现象 | 原因 |
|---|---|
| 「当前页面不是小红书笔记或账号主页」 | 当前标签页不是 xiaohongshu.com |
| 「标题和正文都是空的」 | 不在笔记详情页，或页面还没加载完 |
| 「改用 DOM 兜底」 | 小红书改版了 `__INITIAL_STATE__` 结构，抓到的字段会少 |
| 「没抓到评论」 | 没往下滚动过，评论区还没加载 |
| 「没读到笔记列表」 | 主页还没加载完，或小红书改了主页数据结构 |
| 「未登录，笔记列表可能不全」 | 浏览器里没登录小红书 |
| 点了没反应 | 到 `chrome://extensions/` 点插件的「服务工作进程」看报错 |

DOM 选择器是按当前页面结构写的，小红书改版后可能要调 `extract.js` 里的
`pick([...])` 选择器列表。`__INITIAL_STATE__` 那条路更耐改版，正常情况走的是它。

## 边界

- 手动采集只采你**当前正在看的**这一页，不自动翻页、不后台请求；「依次更新」是唯一会自动打开页面的功能
- 你是真人在真浏览器里正常浏览，点插件的那一刻小红书服务器收不到任何请求
- 采集内容只落本地，不发往任何外部服务
